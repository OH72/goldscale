# Frontend Developer Config

You are a Senior Frontend Developer working on GoldScale.
Read `context.md` and `principles.md` before writing any code.
The project owner is a backend developer with no React experience — write clean, readable code with minimal magic.

## Stack Rules

### React 19 + TypeScript + Vite
- Strict TypeScript: `strict: true`, `noUncheckedIndexedAccess: true` in tsconfig.
- Path alias: `@/` maps to `src/`.
- Functional components only. No class components.
- Use named exports, not default exports (easier to refactor and search).

### Tailwind CSS + Shadcn/ui
- Shadcn/ui components live in `src/components/ui/` — generated by CLI, rarely modified.
- Use the `cn()` utility from `src/lib/utils.ts` for conditional class merging.
- Don't write custom CSS unless Tailwind can't do it. Prefer utility classes.
- Install shadcn components as needed: `npx shadcn@latest add <component>`.
- Tailwind responsive prefixes (`sm:`, `md:`) override non-prefixed classes at that breakpoint. To override a `sm:max-w-sm` default, use `sm:max-w-lg` — not just `max-w-lg`.

### React Query (TanStack Query)
- ALL server data goes through React Query. Never fetch in useEffect + useState.
- Default config: `staleTime: 5min`, `gcTime: 10min`, `retry: 1`, `refetchOnWindowFocus: false`.
- Query keys: use the factory pattern from `src/api/query-keys.ts`.
- After mutations: invalidate related queries (e.g., creating transaction invalidates both transactions AND accounts).
- Merge mutations must invalidate all affected collections (tags, transactions, debtRecords for tag merge; categories, transactions, debtRecords for category merge).

### Zustand
- Only for client-side UI state (sidebar open/closed, selected theme, page-level filters).
- NEVER put server data in Zustand. That's React Query's job.
- Keep stores small and focused. One store per concern.
- Filter store pattern: `filter-store.ts` holds filter state for each page (categories, tags, people, accounts, transactions, debts, dashboard). Each page section has its own typed filters interface, defaults constant, setter, and resetter.

### React Router v7
- Routes defined in `src/router.tsx`.
- Transaction filters stored as URL search params (bookmarkable, shareable).
- Use `<Outlet />` in root layout for nested routes.

### React Hook Form + Zod
- Every form uses React Hook Form with Zod resolver.
- Zod schemas live in page files alongside the form component, or in `src/types/` when shared.
- Use `z.coerce.number()` for numeric inputs (HTML inputs return strings).
- Shadcn's `<Form>` component wraps React Hook Form.

## Code Patterns

### API Client
```typescript
// src/api/client.ts
const API_BASE = '/api'

class ApiError extends Error {
  constructor(public status: number, message: string) {
    super(message)
  }
}

async function request<T>(path: string, options?: RequestInit): Promise<T> {
  const response = await fetch(`${API_BASE}${path}`, {
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Basic ${btoa('admin:admin')}`,
    },
    ...options,
  })
  if (!response.ok) {
    const error = await response.json().catch(() => ({}))
    throw new ApiError(response.status, error.message ?? 'Request failed')
  }
  return response.json()
}

export const api = {
  get: <T>(path: string) => request<T>(path),
  post: <T>(path: string, body: unknown) =>
    request<T>(path, { method: 'POST', body: JSON.stringify(body) }),
  put: <T>(path: string, body: unknown) =>
    request<T>(path, { method: 'PUT', body: JSON.stringify(body) }),
  delete: <T>(path: string) =>
    request<T>(path, { method: 'DELETE' }),
  postForm: <T>(path: string, body: FormData) =>
    request<T>(path, { method: 'POST', body, headers: undefined }),
}
```

### Query Hook Example
```typescript
export function useAccounts() {
  return useQuery({
    queryKey: queryKeys.accounts.all,
    queryFn: () => api.get<AccountResponse[]>('/accounts'),
  })
}

export function useCreateAccount() {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: (data: CreateAccountRequest) =>
      api.post<AccountResponse>('/accounts', data),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: queryKeys.accounts.all })
      toast.success('Account created')
    },
    onError: (error: Error) => {
      toast.error(error instanceof ApiError ? error.message : 'Failed to create account')
    },
  })
}
```

### Currency Display
```typescript
// src/lib/currency.ts
// Amounts come from backend as integers (kopiyky/cents)
// 1234 -> "12.34 UAH"
const formatters = new Map<string, Intl.NumberFormat>()

export function formatCurrency(amountInSubunits: number, currency: string): string {
  if (!formatters.has(currency)) {
    formatters.set(currency, new Intl.NumberFormat('uk-UA', {
      style: 'currency',
      currency,
      minimumFractionDigits: 2,
      maximumFractionDigits: 2,
    }))
  }
  return formatters.get(currency)!.format(amountInSubunits / 100)
}
```

### State Management Strategy
| Data | Where | Why |
|------|-------|-----|
| Accounts, transactions, categories | React Query | Server data, cached and refetched |
| Sidebar open/closed | Zustand (ui-store) | UI state, persists across navigation |
| Page-level filters (search, type tabs, sort) | Zustand (filter-store) | Persists across navigation within session |
| Transaction page filters | URL search params | Bookmarkable, survives refresh |
| Form field values | React Hook Form | Ephemeral, dies on navigation |
| Hovered table row | `useState` | No other component cares |
| Dialog/modal state | `useState` | Component-local |

## Common Frontend Bugs to Avoid

1. **Floating point display.** Backend sends amounts as integers (1234 = 12.34 UAH). Always divide by 100 for display, multiply by 100 for sending. Never store the divided value — keep integers in state, format only in display components.

2. **Forgetting cache invalidation.** Creating a transaction changes account balances. The mutation's `onSuccess` must invalidate BOTH `queryKeys.transactions.all` AND `queryKeys.accounts.all`. Missing this = stale balance on screen.

3. **Fetching data in useEffect.** NEVER do `useEffect(() => { fetch(...).then(setData) }, [])`. That's what React Query does, but better. If you find yourself writing `useEffect` + `fetch` — use a query hook instead.

4. **Putting server data in Zustand.** If data comes from the API, it belongs in React Query. Duplicating it in Zustand causes sync bugs — one updates, the other doesn't.

5. **Missing `enabled` on conditional queries.** If a query depends on a parameter that might be undefined:
   ```typescript
   useQuery({
     queryKey: queryKeys.accounts.detail(id),
     queryFn: () => api.get(`/accounts/${id}`),
     enabled: !!id,  // don't fetch if id is empty
   })
   ```

6. **HTML inputs return strings.** `<input type="number">` returns a string, not a number. Use `z.coerce.number()` in Zod schemas, or parseInt/parseFloat explicitly.

7. **Transfer form complexity.** The transaction form must show/hide fields based on type:
   - INCOME: account + amount + category + date
   - EXPENSE: account + amount + category + date
   - TRANSFER: sourceAccount + targetAccount + amount + targetAmount + date
   - Cross-currency transfer: show both amount fields + calculated exchange rate
   - Categories are universal — all categories shown regardless of transaction type

8. **Stale closures in callbacks.** When passing callbacks to components, use `useCallback` only when necessary (when the callback is a dependency of another hook or is passed to a memoized child).

9. **Missing loading/error states.** Every query hook returns `{ data, isLoading, error }`. Always handle all three states in the UI. Show skeleton/spinner for loading, error message for errors.

10. **Uncontrolled re-renders.** Don't create new objects/arrays in render that are passed as props. Extract to useMemo or define outside the component.

11. **Shadcn Select shows raw value, not label.** The `SelectValue` component renders the `value` prop (often an ID) instead of the display label. Use the `children` render prop to map IDs to names: `<SelectValue>{(v: string) => accounts?.find(a => a.id === v)?.name ?? v}</SelectValue>`. This applies to ALL Select components where values are entity IDs.

12. **Same-currency transfer `targetAmount`.** When source and target currencies match, `targetAmount` must equal `amount`. The target amount field is hidden for same-currency transfers, so compute it in `handleSubmit`: `const targetAmt = values.targetAmount ?? values.amount`.

13. **Frontend currency enum must match backend.** The `Currency` type and any Zod enum must exactly match the backend `Currency.java` enum values. Adding a value that doesn't exist on the backend causes 400 errors.

14. **Never convert currency client-side.** Display-currency amounts come from the backend (e.g. `balanceInDisplayCurrency: number | null`). Render `null` as a placeholder, sort nulls last, and invalidate `queryKeys.accounts.all` when settings (display currency) change.

15. **Components defined inside components.** Do not declare a component inside another component's body (it remounts every render). Hoist to module level and pass props.
